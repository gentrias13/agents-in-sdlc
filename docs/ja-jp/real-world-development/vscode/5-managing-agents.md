GitHub Copilot のエージェント モードでは、コードベースを調査し、変更を提案し、ファイルを編集してコマンドを実行します。作業は自分のマシン上でリアルタイムに行われるため、VS Code の Copilot Chat では各ツール呼び出しやファイル編集の進行状況を確認できます。差分をインラインでレビューし、個別の変更を採用または取り消し、追加のプロンプトで会話の方向を変えたり作業を拡張したりできます。エディターを離れる必要はありません。

この演習では、次のことを行います。

- アクセシビリティ エージェントの作業をリアルタイムで監視します。
- 提案されたファイル編集を確認して採用します。
- セッションの途中でエージェントに指示し、ハイコントラストに加えてライト モードの切り替えを追加します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティ カスタム エージェントが、ハイコントラスト モードを実装しています。作業中にデザイン チームから追加の依頼がありました。既定のテーマが暗すぎると感じるユーザー向けに、ライト モードの切り替えも追加したいとのことです。新たに会話を始めず、既存のセッションに指示を追加して作業を拡張します。

## Copilot の進捗を監視する

Copilot Chat ビューには、エージェントが実行した操作が表示されます。調査したファイル、実行したコマンド、提案した編集などを確認できます。ファイルの編集は差分と **Keep** / **Undo** コントロール付きでチャット内に表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントの作業中にチャットをスクロールし、ツール呼び出しを確認します。ファイルの読み取りと編集、実行を求められるターミナル コマンドが表示されます。
3. エージェントがファイル編集を提案すると、差分がインラインで表示されます。
   - **Keep** を選択すると変更を採用します。
   - **Undo** を選択すると変更を取り消し、エージェントに再度作業させます。
4. チャットの上部にある **Files changed** を開くと、このセッションでエージェントが変更したファイル全体を確認できます。

> [!NOTE]
> ツール呼び出し (たとえばターミナル コマンドの実行) に許可が必要な場合、エージェントは一時停止して **Allow** プロンプトを表示します。内容を確認し、問題ないコマンドのみ許可してください。

5. エージェントがハイコントラスト モードの実装を完了するまで待ちます。実行した変更をまとめたメッセージが表示されます。

## ライト モードを追加するようエージェントに指示する

ハイコントラスト モードが実装されたので、同じ会話にライト モードの切り替え機能も追加します。同じチャット セッションを続けると、エージェントは以前の作業で変更したコンポーネントやスタイルの方針、ローカル ストレージの利用方法などのコンテキストを保持します。

1. Copilot Chat の入力欄に、次のプロンプトを送信します。

   ```plaintext
   よくできました。次はハイコントラストの切り替えに加えてライト モードの切り替えも追加してください。ライト モードも同じパターンにし、local storage に設定を保存して、UI の同じ場所から利用できるようにしてください。ハイコントラストとライト モードは個別に有効化できるようにしてください。
   ```

2. エージェントがすでに加えた変更を調査し、ライト モードの追加を提案します。
3. ハイコントラスト モードと同じように、新しい編集が行われるたびに確認します。それぞれの差分で **Keep** または **Undo** を選択します。
4. エージェントが希望しない方向 (たとえば、好みに合わない形で切り替え UI をリファクタリングするなど) に進んだら、チャット入力欄の横にある **Stop** ボタンで止め、明確な追加メッセージを送信します。

> [!TIP]
> 進行中のセッションに指示を出すほうが、最初から始めるより速く進められます。追加プロンプトを使って変更を依頼できます。たとえば、「CSS を簡素化して、セレクターを複製せず CSS 変数を使う」、「3 つ目のトグルを追加せず、既存の設定パネルにライト モードを統合する」のように方向を修正したり、「両方のトグルにキーボード ショートカットも追加する」のように範囲を広げたりできます。

## 作業内容をレビューする

コミットする前に、エージェントが変更したファイル全体を確認します。

1. VS Code の **Source Control** ビューを開きます。
2. 変更されたファイルの一覧全体を確認します。Astro コンポーネント、スタイル、関連テストなどが更新されているはずです。
3. 変更したファイルをいくつか開いて差分を確認します。カスタム エージェントのアクセシビリティ パターン (ARIA 属性、キーボード操作、セマンティック HTML、local storage による設定の保存) が反映されていることを確認します。
4. 問題がなければ、Source Control パネルから変更をステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat のエージェント モードを使って、進行中のセッションを監視し、指示を追加しました。ファイル編集をその都度確認し、変更を採用または取り消し、コンテキストを失わずに追加のプロンプトを使って作業を拡張しました。

このレッスンでは、次のことを学びました。

- エージェントの作業をリアルタイムで監視する
- 個別のファイル編集を採用または取り消す
- 進行中のセッションに追加プロンプトで指示する

[次のレッスン][next-lesson]では、アクセシビリティの変更をプルリクエストとして公開し、このラボでローカルのカスタム エージェントが生成した内容を確認します。
