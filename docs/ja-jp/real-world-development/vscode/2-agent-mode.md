アプリケーションに簡単な変更を加えるだけでも、通常は複数のファイルを更新し、テストなどを実行する必要があります。開発者は必要なファイルを探し、変更を加え、テストを実行し、デバッグして、変更漏れのファイルを見つけ、さらに修正します。これを繰り返すことになります。

こうした作業には Copilot Agent モードが役立ちます。

Copilot Agent モードは、IDE 内でより自律的に動作します。開発者のように既存のプロジェクト構造を調査し、必要な変更を行い、テストなどを実行して、見つかった問題を自動的に修正します。Agent モードを使ってサイトに新しい機能を追加する方法を確認しましょう。

> [!NOTE]
> 名前は似ていますが、エージェント モードと cloud agent は異なる種類の作業を行います。エージェント モードは IDE 内でタスクを実行し、すばやくフィードバックを受けてやり取りできます。Cloud agent はチーム メンバーのように非同期で作業し、Issue とプルリクエストを通じて連携します。

この演習では、次のことを学びます。

- Copilot Agent モードがプロジェクトを調査し、関連ファイルを特定し、複数の変更を調整する方法
- GitHub Copilot Agent モードで UI とデータ レイヤーにまたがる新機能を実装する方法
- コードベースにマージする前に、Copilot Agent モードが生成した変更とテストをレビューする方法

## シナリオ

ゲームの一覧が増えているため、ユーザーがカテゴリと発行元で絞り込めるようにしたいと考えています。前の演習で発行元ヘルパーを追加しました。今度は Copilot Agent モードを使って、残りのデータ レイヤー、UI、テストを仕上げます。

## Tailspin Toys Web サイトを実行する

変更を加える前に、現在の機能を理解するため Tailspin Toys の Web サイトを確認します。

この Web サイトは、ボードゲームをテーマにしたクラウドファンディング プラットフォームです。ゲームの一覧を表示し、各ゲームの詳細を表示します。このサイトは単一の Astro アプリであり、ビルド時にページを静的 HTML としてレンダリングします。ページは Drizzle ORM を使い、frontmatter 内からローカルの SQLite データベースに直接クエリを実行します。独立したバックエンド API やクライアント側 UI フレームワークはありません。再利用可能なデータ アクセス ヘルパーは `src/lib/` にあり、インタラクティブな動作には標準 DOM API を使う小さな範囲限定の Astro `<script>` を使います。

### Web サイトを起動する

Web サイトを簡単に実行できるよう、単一の Astro 開発サーバーを起動する `npm run dev` タスクが用意されています。GitHub Codespace では、次の手順で起動できます。

1. Codespace に戻ります。前の演習の後で `main` にいることを確認します。
2. <kbd>Control</kbd>+<kbd>\`</kbd> (Mac) または <kbd>Ctrl</kbd>+<kbd>\`</kbd> (Windows/Linux) を押して、新しいターミナルを開きます。
3. 次のコマンドでフィルター作業用の新しいブランチを作成して切り替えます。

   ```bash
   git checkout main
   git pull
   git checkout -b filtering-vscode
   ```

4. 次のコマンドで Web サイトを起動します。

   ```bash
   npm run dev
   ```

   Astro 開発サーバーが準備できると、次のような URL を示すバナーが表示されます。

   ```bash
   🚀 Tailspin Toys is ready!
      Astro server: http://localhost:4321
      Press Ctrl-C to stop.
   ```

> [!NOTE]
> `http://localhost:4321` のブラウザー ウィンドウを開くダイアログが表示された場合は、**x** を選択して閉じます。

5. <kbd>Command</kbd> (Mac) または <kbd>Ctrl</kbd> (Windows/Linux) を押しながら、ターミナルに表示された Astro サーバーのアドレス `http://localhost:4321` を選択して Web サイトを開きます。

> [!NOTE]
> Codespace では、Codespace ターミナルに表示される localhost URL を選択すると、自動的に `https://<your-codespace-name>-4321.app.github.dev/` にリダイレクトされます。これは codespace の Web サーバーを公開するプライベート トンネルです。

### Web サイトを確認する

Web サイトが起動したら、機能を確認します。主な機能は次のとおりです。

- **ホームページ**: ボードゲームのタイトル、画像、説明の一覧を表示します。
- **ゲーム詳細ページ**: ゲームを選択すると、タイトル、説明、発行元、カテゴリなどの詳細を表示します。

## Copilot でバックログを確認する

> [!TIP]
> **Copilot Chat を開く**
>
> 以下の演習を始める前に、codespace に戻り、Copilot Chat パネルを開いて **New Chat** を選択し、新しい会話を開始します。モードとモデルは演習によって異なるため、必要な手順で説明します。

Web サイトの初期実装は機能しますが、さらに機能を追加したいと考えています。まずバックログを確認します。テンプレートからプロジェクトをセットアップすると、Issue のバックログが自動的に作成されます。GitHub Copilot に項目を表示してもらいましょう。

1. Chat ビューのエージェント ドロップダウンから **Agent** を選択します。**Agent** は自律的に計画を立て、複数ファイルを変更し、ターミナル コマンドを実行してツールを呼び出します。

   ![Chat ビューのエージェント ピッカー](../../../_images/shared-chat-mode-selector.png)

2. 利用可能なモデルの一覧から **Claude Sonnet 4.5** を選択します。

> [!CAUTION]
> このワークショップの作成者が特定のモデルを推奨しているわけではありません。ワークショップの作成に Claude Sonnet 4.5 を使ったため、手順にも記載しています。提案されるコードをできるだけ揃えて、学習を進めやすくするためです。ただし、大規模言語モデルは確率的に動作するため、提案が手順と異なる場合があります。これは通常の動作です。

> [!NOTE]
> LLM の確率的な性質により、Copilot が別の MCP コマンドを使うことがありますが、タスクを完了できるはずです。

3. 次のプロンプトを Copilot に送信し、Issue のバックログを確認します。

   ```plaintext
   GitHub リポジトリのバックログを表示してください。ユーザーにとって特に有用な項目を優先するよう、優先順位付けを手伝ってください。
   ```

4. **Continue** を選択して、すべての Issue を一覧表示するコマンドを実行します。
5. Copilot が生成した Issue の一覧を確認します。

Copilot がユーザーにとって特に有用だと考える項目を優先順位付けしたことも確認してください。

## 指示ファイルを確認する

Copilot にコードを生成してもらう前に、作業のコンテキストを伝えるための指示ファイルを確認します。Web サイトへの機能追加方法に関する情報を含む [user interface (UI) 指示ファイル](https://github.com/github-samples/tailspin-toys/blob/main/.github/instructions/ui.instructions.md)を使います。

1. Codespace で `.github/instructions/ui.instructions.md` に移動します。
2. 機能追加に関する全体的なガイダンスを確認します。次の内容が含まれます。
   - アーキテクチャの概要
   - コンポーネント設計、テスト容易性、アクセシビリティの原則
   - Astro、Tailwind CSS、Drizzle など、ファイル形式別の指示ファイルへのリンク

> [!TIP]
> 指示ファイルから、ほかの指示ファイルやプロジェクト内のファイルを参照できます。パスは指示ファイルがある場所を基準にします。これにより指示を再利用でき、複雑な指示を管理しやすい小さなファイルに分割して、例やテンプレートを示せます。

## フィルター機能を実装する

フィルター機能を完成するには、少なくとも 3 つの変更が必要です。

- データ レイヤー (`src/lib/`) に残りのフィルター ロジックを追加または調整する
- フィルターの動作に関するテストを追加または更新する
- ゲーム一覧ページを更新して、フィルター UI を追加する

さらに、コードベースにマージする前にテストを実行して成功させる必要があります。Copilot Agent モードに作業を依頼しましょう。

1. 現在の Copilot との会話を続けるか、**New Chat** を選択して新しい会話を開始します。
2. **Add Context**、**Instructions**、**ui** の順に選択し、指示ファイルを追加します。

   ![UI 指示ファイルを選択する例](../../../_images/ex3-select-instructions-file.png)

3. Chat ビューのエージェント ドロップダウンで **Agent** が選択されていることを確認します。

   ![Chat ビューのエージェント ピッカー](../../../_images/shared-chat-mode-selector.png)

4. モデルが引き続き **Claude Sonnet 4.5** であることを確認します。
5. 次のプロンプトを使って、バックログの関連 Issue に基づいて機能を実装するよう Copilot に依頼します。

   ```plaintext
   バックログにある関連 GitHub Issue の要件に基づいて、サイトに発行元とカテゴリによるフィルターを追加してください。前の演習で発行元ヘルパーはすでに作成しているため、その作業を保持して必要に応じて改善し、残りのデータ レイヤー、UI、テストを完了してください。完了前に、すべてのテストが成功することを確認してください。サーバーはすでに起動しているため、起動し直す必要はありません。
   ```

6. Copilot がプロジェクトを調査し、データ レイヤーのヘルパー、UI、テストなど、機能に関連するファイルを見つけて変更し、テストを実行する様子を確認します。

   ![Copilot がプロジェクト ファイルを調査する画面](../../../_images/ex3-agent-mode-explores.png)

> [!NOTE]
> Copilot はプロジェクトの調査、ファイルの変更、テストの実行など複数の作業を行います。タスクやコードベースの複雑さによって数分かかることがあります。処理中にコード エディターに **Keep** や **Undo** ボタンが表示されることがあります。作業中に選択する必要はなく、Copilot の完了後にすべての変更に対して **Keep** または **Undo** を選択できます。

7. Copilot の指示に従って **Continue** を選択し、テストを実行します。

   ![Copilot Chat がテスト実行の確認を求めるダイアログ](../../../_images/ex3-agent-mode-run-tests.png)

8. 処理中に一時停止したり、テストが失敗したりすることがあります。問題ありません。Copilot はタスクの完了と判断し、エラーを検出しなくなるまでコード生成とテストを繰り返します。

   ![Copilot Agent モードの完了したチャット セッション](../../../_images/ex3-agent-mode-proposed-changes.png)

9. 生成されたコードに問題がないか確認します。

> [!CAUTION]
> Copilot などの AI ツールが生成したコードは、必ずレビューしてください。

10. Web サイトを表示しているブラウザーに戻り、新機能を試します。
11. すべてが動作することを確認し、コードをレビューしたら、Copilot Chat ウィンドウで **Keep** を選択します。

### ボーナス演習 — ページネーションを実装する

ゲームの一覧が増えると、ページネーションが必要になります。この演習で学んだ方法を使い、Copilot にページネーションを実装するよう依頼します。次の点を検討してください。

- 既存の指示ファイルを使うなど、既存のベスト プラクティスに従います。
- ユーザーがページ サイズを選択できるようにするか、サイズを固定するかなど、ページネーションの動作を検討します。
- 希望する実装に必要なガイダンスをプロンプトに含めます。
- Copilot に変更を依頼してコンテキストを提供しながら、何度か反復する場合があります。Copilot との通常の作業方法です。
