最初は小さな機能を追加しました。より大きな変更には、さらに堅牢なプロセスが必要です。GitHub Copilot CLI は組織の既存の開発フローに沿って動作するため、適切なものを適切な方法で構築できます。このレッスンから、Issue を使って機能を実装し、コードが有効であること、機能が期待どおりに動作することを確認して、プロジェクトにマージする、一般的なエージェント主導の開発プロセスを進めます。

> [!NOTE]
> この機能のワークフローでは、同じ会話とブランチを使います。通常は、扱うファイルの種類に応じてブランチや PR を分けますが、ここでは主要な概念に集中できるよう簡略化しています。

このレッスンでは、次のことを行います。

- GitHub Issue から Copilot の会話を開始します。
- Plan モードで要件を定義します。
- Autopilot モードで機能を実装します。
- コードをレビューします。
- 転送されたブラウザーで手動検証します。

この機能に取り組む中で、リポジトリの指示を更新し、既存の `quality-checks` スキルをカスタマイズし、MCP による検証を追加し、QA エージェントを作成して、最後に機能 PR を作成します。

## シナリオ

Tailspin Toys のカタログが増え、訪問者がカテゴリと発行元でゲームを絞り込めるようにする必要があります。バックログの Issue には機能の概要がありますが、カテゴリを組み合わせる方法など、実装前に合意が必要な詳細もあります。Plan モードで方針を決めてから、範囲を定めた実装を Autopilot に許可します。

## 背景

AI コーディング エージェントを開発フローに導入しても、基本は変わりません。むしろ、重要性は増します。多くの開発者は次のような流れで作業します。

1. 実装内容を記述した Issue から始めます。
2. 構築する内容を計画します。
3. コードを作成してレビューします。
4. テストを実行してコードを検証します。
5. 新しい機能を手動で検証します。
6. プルリクエスト (PR) を作成します。
7. コードレビューと継続的インテグレーションが成功したら、コードをマージします。

> [!NOTE]
> チームや組織によって具体的な手順は異なりますが、多くはこの流れをベースにしています。

この標準的な進め方に沿うことで、AI が生成したコードが要件を満たし、手書きのコードと同じ検証プロセスを経るようにできます。

## 会話モード

**会話モード**は、エージェントにどの程度の自律性を持たせるかを制御します。<kbd>Shift</kbd>+<kbd>Tab</kbd> を押すとモードを切り替えられます。

- **Interactive**: エージェントが変更を提案し、次に進む前にユーザーの入力を待ちます。
- **Plan**: エージェントが先に計画を作成します。プロジェクト ファイルの編集はできません。
- **Autopilot**: エージェントが自律的にコードを書き、テストを実行し、タスクが完了するまで反復します。

まず Plan モードで計画を確認し、その後 Autopilot で実装します。

## Issue から始める

フィルターの作業を始める前に、Codespace に戻り、リポジトリとターミナルの準備ができていることを確認します。

1. Codespace に戻ります。停止している場合は再起動します。
2. 星評価の PR がマージ済みであることを確認します。
3. ターミナルが開いていない場合は、<kbd>Control</kbd>+<kbd>\`</kbd> (Mac) または <kbd>Ctrl</kbd>+<kbd>\`</kbd> (Windows/Linux) を押します。
4. `main` を更新し、フィルター用ブランチを作成します。

   ```bash
   git checkout main
   git pull --ff-only
   git checkout -b game-filters-cli
   ```

5. Copilot CLI を起動します。

   ```bash
   copilot --yolo
   ```

6. <kbd>Tab</kbd> を 2 回押して **Issues** タブを開きます。
7. <kbd>A</kbd> を押してすべての Issue を表示します。
8. 矢印キーで **Allow users to filter games by category and publisher** というタイトルの Issue を選択します。
9. <kbd>C</kbd> を押して Issue をプロンプトに追加し、**Session** タブに戻ります。

プロンプトが `#7` (または同様の番号) で始まっていることを確認してください。`#` を使うと、GitHub 上の Issue やプルリクエスト (PR) をコンテキストに追加できます。

## フィルター機能を計画する

計画を立てると、機能を実装したりタスクを実行したりする前に、アプローチを定義できます。複雑な作業では、時間をかけて計画することをお勧めします。Plan モードに切り替えて、Copilot に計画を作成してもらいましょう。

1. <kbd>Shift</kbd>+<kbd>Tab</kbd> を押して Plan モードに切り替え、プロンプトの下に **Plan** と表示されていることを確認します。
2. 前の手順で追加した Issue の後に、次のプロンプトを入力します。

   ```plaintext
   この機能を実装する計画を作成してください。
   ```

Copilot がプロジェクトを調査し、最適なアプローチを判断して計画を作成します。

3. フィルターの動作について質問されたら、希望に沿って回答します。正解は 1 つではありません。
4. 計画ができたら、<kbd>Control</kbd>+<kbd>E</kbd> (Mac) または <kbd>Ctrl</kbd>+<kbd>E</kbd> (Windows/Linux) を押して計画を展開します。
5. 計画を上下にスクロールして確認します。
6. 自分の判断と一致しない箇所があれば、Copilot に修正を依頼します。

## Autopilot を承認する

計画を作成して確認したので、実装に進みます。Autopilot を使って Copilot に作業を任せましょう。

Autopilot では、Copilot が完了したと判断するまでタスクを反復できます。

1. **Accept plan and build on autopilot (recommended)** またはインストールしたバージョンで同様の名前のオプションを選択します。
2. プロンプトの下に **Autopilot** と表示されていることを確認します。
3. Copilot が計画に沿ってコードを生成し、テストを実行する様子を確認します。

> [!NOTE]
> 承認するとすぐに実装が始まる場合があります。先に計画を確認してください。Copilot が依存関係の不足やポートの競合を報告した場合は、チェックが完了したと判断する前にセットアップの問題を解決してください。

## 実装をレビューして検証する

生成されたコードは、ほかのコードと同様にマージ前にレビューします。コードを確認し、サイトを実行して問題がないことを確認しましょう。

1. <kbd>Shift</kbd>+<kbd>Tab</kbd> を押して Interactive モードに切り替え、モード表示に **Plan** も **Autopilot** もないことを確認します。
2. `/diff` を入力し、フィルターの実装とテストを調べます。
3. 結果を Issue および計画での決定事項と照らし合わせます。
4. レビューが終わったら <kbd>Esc</kbd> を押して差分画面を終了します。
5. プロジェクトのチェック結果を確認し、失敗があれば Copilot に解決を依頼します。

## 新しい機能を試す

コードに問題がなさそうでも、実際に動作するか確認します。前と同様にアプリを起動し、Codespaces で転送されたポートからサイトを開きましょう。

1. Copilot に次のように依頼してアプリを起動します。

   ```plaintext
   ブラウザーでフィルター機能を試せるよう、アプリを起動してください。URL を教えて、サーバーは起動したままにしてください。
   ```

2. Codespaces でポート `4321` が利用可能になったら、**Open in Browser** を選択します。
3. カテゴリと発行元によるフィルターを試し、計画で合意した組み合わせも確認します。
4. リセットと検索結果がない場合の動作が Issue と決定事項に合っていることを確認します。
5. Codespace に戻り、Copilot に起動した開発サーバーの停止を依頼します。

## まとめと次のステップ

さまざまな会話モードを使って機能を構築し、レビューしました。このレッスンでは、次のことを行いました。

- GitHub Issue から Copilot の会話を開始しました。
- Plan モードで要件を定義しました。
- Autopilot モードで機能を実装しました。
- コードをレビューしました。
- 転送されたブラウザーで機能を手動検証しました。
