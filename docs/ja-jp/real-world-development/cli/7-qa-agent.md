これまでに `quality-checks` スキルを使って自動チェックを実行し、Playwright MCP でブラウザーからフィルター機能を確認しました。今度は、これらの機能を明確な QA プロセスを持つカスタム エージェントにまとめます。

このレッスンでは、次のことを行います。

- カスタム エージェントが指示、スキル、MCP ツールと連携する方法を確認します。
- 再利用可能な品質保証プロファイルを作成して調べます。
- QA エージェントを選び、フィルターの Issue に照らして結果をレビューします。

## シナリオ

Tailspin Toys では、プルリクエスト (PR) を作成する前に、要件、コード品質、自動チェック、テスト範囲、ブラウザーでの動作を一貫してレビューしたいと考えています。カスタム エージェントを使うと QA プロセスを調整し、再利用できるレポートを作成できます。

## カスタム エージェントとは

カスタム エージェントは、Markdown プロファイルで定義する Copilot の専門的なバージョンです。目的、指示、利用可能なツールを記述します。このワークショップでは `.github/agents/qa.agent.md` に QA の役割を定義し、Copilot CLI で選択します。

これまで使ってきたカスタマイズにはそれぞれ別の役割があります。リポジトリの指示はチームの標準を説明し、`quality-checks` スキルは再利用可能なチェックをまとめ、Playwright MCP はブラウザー ツールを提供します。QA プロファイルは、要件を評価して結果を報告するために、Copilot がこれらの機能をどのように使うかを示します。これらを置き換えたり、別の会話を開始したりするものではありません。

## QA プロファイルを作成する

機能 PR を作成する前に、再利用可能な QA プロファイルを作るよう Copilot に依頼します。プロファイルには、QA が実行するチェックと守るべき境界を定義します。

1. Codespace に戻り、フィルターの会話が Interactive モードであることを確認します。
2. 既定のエージェントに次のプロンプトを使って新しいカスタム エージェントを作成するよう依頼します。

   ```plaintext
   `.github/agents/qa.agent.md` に QA という名前のカスタム エージェントを作成してください。Issue と合意した要件に照らして機能を確認し、リポジトリの指示に従い、`quality-checks` スキルを実行し、Playwright MCP で動作を検証し、テスト範囲が不足している場合はテストを追加するようにしてください。

   各要件について、根拠とともに成功、失敗、またはブロックされた状態を報告するようにしてください。実装コードを変更する前には必ず確認を求め、変更をコミットしたりプルリクエストを作成したりしないようにしてください。

   まずプロファイルだけを作成し、確認できるようにしてください。
   ```

## プロファイルを確認する

新しいエージェントを使う前に、意図した QA ワークフローと境界がプロファイルに記載されていることを確認します。検証だけを依頼したのに、Copilot が機能を変更してしまうのを防げます。

1. `/diff` を入力して `.github/agents/qa.agent.md` を開きます。
2. frontmatter を読みます。`description` は必須です。`name` は任意ですが、含めるとエージェントの表示名が明確になります。
3. プロファイルの指示を読み、QA が要件から始め、リポジトリの指示に従い、`quality-checks` スキルを実行して Playwright MCP を使うことを確認します。
4. QA が根拠を示して結果を報告し、実装コードを変更する前に確認を求め、変更のコミットやプルリクエストの作成を行わないことを確認します。
5. これらの責任や境界が抜けていたら、続行する前に既定のエージェントに修正を依頼します。

## Issue に対して QA を実行する

Copilot CLI は会話の開始時にプロジェクトのエージェントを読み込みます。プロファイルを作成した後、同じフィルターの会話を再開し、QA を選んで、コンテキストにある Issue と計画での決定事項を使えるようにします。

1. 次のプロンプトを使ってエージェントを有効にします。

   ```plaintext
   /agent QA
   ```

> [!NOTE]
> 新しく作成したエージェントが、利用可能なエージェントの一覧に表示されないことがあります。次のコマンドで有効化できます。

2. 次のプロンプトで QA エージェントに機能のレビューを依頼します。

   ```plaintext
   Issue と計画での決定事項に照らしてフィルター機能をレビューしてください。PR を作成できる状態ですか。
   ```

3. QA エージェントが作業を始めます。
4. 作業が終わったら、レポートを確認します。

- 再利用可能な品質保証プロファイルを作成して調べました。
- QA エージェントを選び、フィルターの Issue に照らして結果をレビューしました。
