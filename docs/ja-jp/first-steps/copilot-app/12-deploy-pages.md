GitHub Pages で Space Quiz をデプロイし、誰でもアクセスできる場所に公開しましょう。Copilot はワークフローの準備とデプロイを支援しますが、変更を確認してサイトが公開されたことを確かめるのは自分の役割です。

このレッスンでは、次のことを行います。

- Copilot に GitHub Pages のデプロイを構成するよう依頼します。
- マージする前にワークフローとプルリクエストを確認します。
- デプロイを追跡し、公開されたサイトを検証します。

## シナリオ

Space Quiz はすでに GitHub リポジトリにありますが、簡単に試せる方法が必要です。単一ファイルのサイトを GitHub Pages で公開すれば、サーバーやランタイム依存関係を追加せずに、公開 URL からアクセスできるようになります。

## Copilot にサイトのデプロイを依頼する

`space-quiz` の Copilot app セッションで、次のプロンプトを送信します。

```plaintext
このリポジトリで GitHub Pages を有効にしてください。必要に応じて Web サイトをビルドし、GitHub Pages にデプロイする GitHub Actions ワークフローを作成してください。README がまだない場合は、アプリとローカルでの実行方法を説明する README を追加してください。変更を含むプルリクエストを作成し、必須チェックの成功後にマージしてください。デプロイを監視して成功したら、公開サイトの最終 URL を報告してください。Pages の有効化やマージの権限がない場合は、何を承認または実行すればよいかを具体的に教えてください。サイトが公開されるまでは成功と報告しないでください。
```

> [!WARNING]
> このプロンプトでは、エージェントにプルリクエストの作成とマージ、およびリポジトリの Pages 設定の変更を依頼します。続行する前に、差分、デプロイの権限、GitHub の承認要求を確認してください。

## ワークフローを確認してデプロイを検証する

1. README は、リポジトリにまだ存在しない場合にのみ追加されていることを確認します。
2. ワークフローのビルド手順とデプロイ手順を含め、プルリクエストの変更を確認します。
3. 必須のプルリクエスト チェックが成功した後にのみマージします。
4. GitHub Actions のデプロイ実行が成功するまで確認します。
5. 報告された URL を開き、Space Quiz が読み込まれることを確認します。

エージェントが Pages の有効化やプルリクエストのマージを行えない場合は、提示された具体的な手順に従ってください。デプロイが成功し、公開サイトが表示されるまでは、作業を完了と見なさないでください。
