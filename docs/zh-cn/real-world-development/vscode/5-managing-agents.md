在智能体模式下使用 GitHub Copilot 时，它会自主探索代码库、提出更改、编辑文件并运行命令。Copilot Chat 在 VS Code 中实时展示工具调用和文件编辑。你可以在聊天中查看每项差异、接受或拒绝单个更改，并通过后续提示引导对话，在不离开编辑器的情况下改进或扩展工作。

本练习将介绍如何：

- 实时监控无障碍智能体的工作。
- 审查并接受建议的文件编辑。
- 在会话中途引导智能体添加浅色模式切换。

## 场景

你在[练习 4][previous-lesson]中使用的无障碍自定义智能体正在实现高对比度模式。工作进行期间，设计团队提出了新要求：为偏好较浅界面的用户增加浅色模式切换。无需从头开始新建对话，而是在现有会话中引导智能体扩展功能。

## 监控 Copilot 的进度

Copilot Chat 视图会显示智能体的每一步操作，包括探索的文件、运行的命令和提出的编辑。每项文件编辑都会在聊天中以内嵌差异显示，并带有 **Keep** 和 **Undo** 控件。

1. 返回练习 4 中的 Copilot Chat 视图。
2. 智能体工作时，在聊天中查看每次工具调用，包括文件读取、编辑和请求运行的终端命令。
3. 智能体提出文件编辑时，差异会以内嵌形式显示：
   - 选择 **Keep** 接受更改。
   - 选择 **Undo** 撤销更改，让智能体重新尝试。
4. 也可以打开聊天顶部的 **Files changed** 指示器，查看智能体在本次会话中修改的所有文件。

> [!NOTE]
> 如果工具调用需要权限（例如运行终端命令），智能体会暂停并显示 **Allow** 提示。只批准你认可的命令。

5. 等待智能体完成高对比度模式。完成后会看到总结更改的消息。

## 引导智能体添加浅色模式

现在已有高对比度模式，可以在同一对话中继续添加浅色模式切换。智能体会保留之前工作的上下文，包括修改的组件、采用的样式方法和设置的本地存储模式。

1. 在 Copilot Chat 输入框中发送以下后续提示：

    ```plaintext
    做得好！现在在高对比度切换开关旁边添加浅色模式开关。浅色模式应采用相同模式，通过 local storage 保存设置，并可从 UI 的同一区域访问。用户应能分别启用高对比度模式和浅色模式。
    ```

2. 智能体会从当前进度继续，检查已有更改并提出浅色模式的补充内容。
3. 像审查高对比度模式那样查看每项新编辑，并针对每个差异选择 **Keep** 或 **Undo**。
4. 如果智能体的实现方向不符合预期（例如尝试以不合意的方式重构切换 UI），可以选择聊天输入框旁的 **Stop** 按钮停止任务，再发送澄清后的提示。

> [!TIP]
> 引导正在运行的会话比从头开始更快。可以使用后续提示提出调整要求（“简化 CSS，改用 CSS 变量，不要重复选择器”）、纠正方向（“不要添加第三个切换项，将浅色模式整合到现有设置面板”），或扩展范围（“为两个切换项添加键盘快捷键”）。

## 审查工作集

提交更改前，快速检查智能体修改的所有内容。

1. 在 VS Code 中打开 **Source Control** 视图。
2. 查看已更改文件的完整列表。应包含 Astro 组件、样式和相关测试的更新。
3. 打开几个已更改的文件并检查差异。确认其中体现了自定义智能体要求的无障碍模式，例如 ARIA 属性、键盘导航、语义化 HTML 和本地存储持久化。
4. 确认无误后，在 Source Control 面板中暂存并提交更改。下一课会发布这些更改。

## 总结和后续步骤

你使用 Copilot Chat 智能体模式监控并引导正在进行的会话：审查逐步生成的文件编辑、接受或拒绝更改，并在保留上下文的情况下通过后续提示扩展工作。本课中，你：

- 实时监控智能体的工作。
- 接受或拒绝单项文件编辑。
- 使用后续提示引导正在进行的会话。

接下来将无障碍功能发布为 pull request，并审查本实验中本地自定义智能体生成的更改。
